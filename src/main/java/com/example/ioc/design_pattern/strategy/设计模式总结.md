# 设计模式总结

本包（`com.example.ioc.design_pattern.strategy`）下的 demo 主要实现了支付场景的灵活扩展，涉及以下设计模式：

## 1. 策略模式（Strategy Pattern）

**类/接口：** `PayFacade`（接口）、`AliPay`、`WeiXinPay`（实现类）

**作用：**
- 定义统一的支付接口 `PayFacade`，不同支付方式实现各自的支付逻辑。
- 通过注册机制，将不同支付实现与场景（`Scene` 枚举）关联，客户端根据场景选择对应策略。

**代码片段：**
```java
public interface PayFacade extends InitializingBean {
    void pay();
    Scene getSupportScene();
    @Override
    default void afterPropertiesSet() {
        PayFactory.register(getSupportScene(), this);
    }
}

@Component
public class AliPay implements PayFacade {
    @Override
    public void pay() {
        // 支付宝支付逻辑
    }
    @Override
    public Scene getSupportScene() {
        return Scene.ALIBABA;
    }
}
```

## 2. 工厂模式（Factory Pattern）

**类/接口：** `PayFactory`

**作用：**
- 通过工厂类统一获取不同场景下的支付实现。
- 利用注册表，将场景与支付实现解耦，便于扩展。

**代码片段：**
```java
public class PayFactory {
    private static final Map<Scene, PayFacade> PAY_FACADE = new HashMap<>();
    public static void register(Scene scene, PayFacade payFacade) {
        PAY_FACADE.put(scene, payFacade);
    }
    public static PayFacade get(Scene scene) {
        return PAY_FACADE.get(scene);
    }
}
```

## 3. 枚举（Enum）与注册表模式

**类/接口：** `Scene`（枚举）、`PayFactory`（注册表）

**作用：**
- 使用枚举定义支付场景（如 TENCENT、ALIBABA），提升类型安全。
- 通过注册表模式，将场景与实现类动态绑定。

**代码片段：**
```java
public enum Scene {
    TENCENT,
    ALIBABA
}
```

## 4. 依赖注入（Dependency Injection，Spring 框架特性）

**类/接口：** `AliPay`、`WeiXinPay`（@Component 注解）

**作用：**
- 利用 Spring 的 `@Component` 注解，实现支付服务的自动注册和注入，解耦对象创建和使用。
- 结合 `InitializingBean` 接口，Bean 初始化时自动注册到工厂。

---

## 总结

本 demo 通过策略模式+工厂模式+注册表模式，实现了支付服务的灵活扩展和解耦，结合 Spring 的依赖注入，极大提升了代码的可维护性和可扩展性。
