# 设计模式总结

本包（`com.example.ioc.design_pattern.inwork`）下的 demo 主要实现了支付服务的扩展与解耦，涉及以下设计模式：

## 1. 工厂模式（Factory Pattern）

**类/接口：** `PayServiceFactory`

**作用：**
- 通过工厂类统一获取不同的支付服务实例（如支付宝、微信）。
- 利用 Spring 的依赖注入，将所有实现了 `PayService` 接口的 Bean 自动注入到 `payServiceMap`，通过 key（如 `alipayPayService`、`wechatPayService`）动态获取对应的支付实现。

**代码片段：**
```java
@Autowired
public Map<String, PayService> payServiceMap = new ConcurrentHashMap<>();

public PayService getPayService(String payChannel) {
    return payServiceMap.get(payChannel + "PayService");
}
```

## 2. 策略模式（Strategy Pattern）

**类/接口：** `PayService`（接口）、`AlipayPayService`、`WechatPayService`（实现类）

**作用：**
- 定义统一的支付接口 `PayService`，不同支付方式实现各自的支付逻辑。
- 通过工厂模式+策略模式，客户端只需根据类型获取对应策略，无需关心具体实现。

**代码片段：**
```java
public interface PayService {
    void pay(PayRequest payRequest);
}

public class AlipayPayService extends AbstractPayService {
    @Override
    public void doPay(PayRequest payRequest) {
        // 支付宝支付逻辑
    }
}
```

## 3. 模板方法模式（Template Method Pattern）

**类/接口：** `AbstractPayService`（抽象类）

**作用：**
- 在抽象类中定义支付流程的模板方法 `pay`，包括参数校验、具体支付、后置处理等步骤。
- 具体支付逻辑由子类实现（如 `AlipayPayService`、`WechatPayService`），流程骨架由父类统一控制。

**代码片段：**
```java
public abstract class AbstractPayService implements PayService {
    @Override
    public void pay(PayRequest payRequest) {
        validateRequest(payRequest);
        doPay(payRequest);
        postPay(payRequest);
    }
    public abstract void doPay(PayRequest payRequest);
    protected void postPay(PayRequest payRequest) {}
    protected void validateRequest(PayRequest payRequest) {}
}
```

## 4. 依赖注入（Dependency Injection，Spring 框架特性）

**类/接口：** `PayServiceFactory`、各支付服务实现类

**作用：**
- 利用 Spring 的 `@Service`、`@Autowired` 注解，实现支付服务的自动注册和注入，解耦对象创建和使用。

---

## 总结

本 demo 通过工厂模式+策略模式+模板方法模式，实现了支付服务的灵活扩展和解耦，结合 Spring 的依赖注入，极大提升了代码的可维护性和可扩展性。
